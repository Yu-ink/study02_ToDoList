# PRD: 오늘 할 일 (개인용 To-Do 웹앱)

- 작성일: 2026-10-01
- 상태: 승인됨 (구현 전)

## 1. 개요

### 1.1 목적
매일 10~20개 정도의 할 일을 관리하는 **개인용** 웹앱. "오늘" 하루에 집중해 할 일을 추가·정리·완료하고, 진행 상황을 한눈에 확인한다.

### 1.2 핵심 원칙
- **바로 실행**: 설치·서버·빌드 없이 `index.html`을 브라우저로 열면 동작한다 (`file://` 지원).
- **데이터 유지**: 새로고침하거나 브라우저를 닫았다 열어도 데이터가 남는다 (`localStorage`).
- **단순함**: 순수 HTML/CSS/JavaScript만 사용한다. 프레임워크·라이브러리·빌드 도구 없음.

### 1.3 사용자
- 본인 1명. 데스크톱 브라우저 위주, 모바일 브라우저에서도 사용 가능해야 함.
- 로그인·공유·동기화 없음.

## 2. 기능 요구사항

### 2.1 할 일 추가
- 상단 입력창에 내용을 입력하고 카테고리(업무/개인/공부)를 선택한 뒤 Enter 또는 [추가] 버튼으로 추가한다.
- 새 항목은 **미완료 목록의 맨 아래**(완료 항목보다는 위)에 들어간다.
- 앞뒤 공백을 제거한 내용이 비어 있으면 추가하지 않는다.
- 내용은 최대 200자.
- 카테고리 선택값은 마지막으로 고른 값을 기억한다 (새로고침 후에도 유지).
- 추가 후 입력창은 비워지고 포커스를 유지한다.

### 2.2 할 일 수정
- 텍스트 더블클릭 또는 ✏️ 버튼으로 해당 항목이 인라인 편집 상태가 된다. 내용과 카테고리를 수정할 수 있다.
- Enter 또는 입력창 밖 클릭(blur) → 저장. Esc → 취소.
- 내용을 비운 채 저장하면 **취소로 처리**한다 (삭제하지 않음).
- 동시에 하나의 항목만 편집 상태가 될 수 있다.

### 2.3 할 일 삭제
- 🗑 버튼을 누르면 확인 창 없이 즉시 삭제한다.
- 화면 하단에 **"삭제됨 · 실행 취소"** 토스트를 5초간 표시한다. [실행 취소]를 누르면 원래 위치에 복원한다.
- 토스트가 떠 있는 중에 다른 항목을 삭제하면, 이전 삭제는 확정되고 토스트는 새 삭제 기준으로 갱신된다 (실행 취소는 마지막 1건만).

### 2.4 완료 체크
- 체크박스로 완료/미완료를 토글한다.
- 완료 시: 취소선 + 흐린 표시, 항목이 **완료 목록의 맨 위**로 이동한다 (최근 완료가 위). `completedAt` 기록.
- 완료 해제 시: **미완료 목록의 맨 아래**로 이동한다. `completedAt`은 `null`.
- 미완료 목록과 완료 목록 사이에 `완료 (N)` 구분선을 표시한다. 완료 항목이 0개면 구분선을 숨긴다.

### 2.5 순서 변경
- **미완료 항목만** 순서를 바꿀 수 있다. 완료 항목은 완료 시각 역순으로 고정.
- 방법 두 가지:
  - 드래그 앤 드롭 (⠿ 핸들, HTML5 Drag and Drop API)
  - ▲▼ 버튼 (모바일·키보드 대응). 맨 위 항목의 ▲, 맨 아래 미완료 항목의 ▼는 비활성.
- 필터 탭이 적용된 상태에서는 **화면에 보이는 항목끼리** 순서를 바꾼다. (예: "업무" 탭에서 ▼ → 다음 업무 항목과 자리 교환. 사이의 다른 카테고리 항목들의 상대 순서는 유지)

### 2.6 카테고리와 필터
- 카테고리는 3개로 고정: `work`(업무, 파랑), `personal`(개인, 초록), `study`(공부, 보라).
- 각 항목에 카테고리 색상 태그를 표시한다.
- 목록 상단 필터 탭: `전체 / 업무 / 개인 / 공부`. 선택한 탭은 새로고침 후에도 유지.
- 필터 결과가 비면 "업무 할 일이 없어요"처럼 해당 카테고리 이름으로 안내한다.

### 2.7 진행률
- **전체 진행률**: `완료 수 / 오늘 할 일 수`를 진행 바 + `7 / 12 · 58%` 형식으로 표시. 퍼센트는 반올림 정수.
- **카테고리별 진행률**: 업무/개인/공부 각각 `완료/전체`와 작은 진행 바. 할 일이 0개인 카테고리는 `–`로 표시.
- 진행률은 필터 탭과 무관하게 **항상 오늘 전체 기준**으로 계산한다.
- 오늘 할 일이 0개면 진행률 영역 대신 "오늘 할 일을 추가해보세요" 안내를 표시한다.

### 2.8 날짜 넘김 (이월)
- 모든 할 일은 `date`(로컬 기준 `YYYY-MM-DD`)를 가진다. 화면은 항상 "오늘" 날짜의 할 일만 다룬다.
- 다음 시점에 날짜를 확인한다:
  - 앱 시작 시
  - 탭이 다시 보이게 될 때 (`visibilitychange`)
  - 할 일을 바꾸는 사용자 조작(추가·체크·삭제·순서 변경 등) 직전 — 자정을 넘겨 앱을 켜 둔 경우 대비
- 오늘보다 이전 날짜의 항목이 있으면:
  - **미완료 항목** → `date`를 오늘로 변경 (이월). 배열 안의 기존 순서는 그대로 유지.
  - **완료 항목** → 삭제.
- 이월된 항목에 별도 표시는 하지 않는다.
- 헤더에 오늘 날짜를 `2026년 10월 1일 (목)` 형식으로 표시한다.

## 3. 데이터 설계

### 3.1 할 일 객체
```js
{
  id: "t_1727751234567_x3k",  // 생성 시각(ms) + 난수 3자
  text: "보고서 초안 작성",      // 1~200자, 앞뒤 공백 제거
  category: "work",           // "work" | "personal" | "study"
  done: false,
  date: "2026-10-01",         // 로컬 기준 YYYY-MM-DD
  createdAt: 1727751234567,   // ms
  completedAt: null           // ms 또는 null
}
```

### 3.2 저장 형식
| 키 | 값 |
|---|---|
| `todoapp.v1` | `{ "version": 1, "todos": [ ... ] }` |
| `todoapp.v1.prefs` | `{ "filter": "all", "lastCategory": "work" }` |
| `todoapp.v1.backup` | 손상된 데이터 원본 (오류 시에만 생성) |

- **배열 순서 = 화면 순서.** 별도 `order` 필드 없음. 순서 변경은 배열 내 위치 이동으로 처리.
- 배열은 항상 `[미완료들..., 완료들(최근 완료 순)...]` 형태를 유지한다 (불변 조건).
- 모든 변경(추가/수정/삭제/체크/순서 변경/이월) 직후 즉시 저장.
- `version` 필드로 향후 구조 변경 시 마이그레이션.

### 3.3 날짜 계산
- 날짜 문자열은 **로컬 시간**의 연/월/일로 만든다. `toISOString()`은 UTC 기준이라 한국(UTC+9)에서 오전 9시 이전에 전날로 계산되므로 사용 금지.

## 4. 기술 설계

### 4.1 파일 구조
```
index.html        앱 진입점
style.css         스타일 (라이트/다크)
js/storage.js     localStorage 읽기/쓰기 (JSON 봉투, 손상 시 백업)
js/todos.js       할 일 로직 — DOM을 모르는 순수 함수 (저장 데이터 항목 검증 포함)
js/ui.js          렌더링, 이벤트 처리, 드래그 앤 드롭, 토스트
js/app.js         초기화, 상태 보관, 모듈 연결
tests.html        테스트 러너 (브라우저로 열기)
tests/harness.js  최소 테스트 도구 (test / assert / assertEqual)
tests/*.test.js   todos.js, storage.js 테스트
```

### 4.2 모듈 규칙
- ES 모듈(`import/export`)은 `file://`에서 CORS로 차단되므로 **일반 `<script>` 태그**를 사용한다.
- 각 파일은 전역 네임스페이스 객체 하나만 노출한다: `window.TodoStorage`, `window.Todos`, `window.TodoUI`. 파일 내부는 IIFE로 감싼다.
- 로드 순서: `storage.js` → `todos.js` → `ui.js` → `app.js`.

### 4.3 todos.js (순수 함수)
상태를 직접 바꾸지 않고 **새 배열을 반환**한다. "오늘"·"현재 시각"은 인자로 받는다 (테스트 가능하도록).

| 함수 | 설명 |
|---|---|
| `addTodo(todos, { text, category }, now)` | 미완료 맨 아래에 추가 |
| `updateTodo(todos, id, { text?, category? })` | 내용/카테고리 수정. 빈 text는 무시 |
| `removeTodo(todos, id)` | 삭제. `{ todos, removed, index }` 반환 (실행 취소용) |
| `restoreTodo(todos, removed, index)` | 삭제 취소 |
| `toggleTodo(todos, id, now)` | 완료/해제 + 위치 이동 |
| `moveTodo(todos, id, 'up' \| 'down', visibleIds)` | ▲▼ 이동 (보이는 항목 기준) |
| `reorderTodo(todos, id, targetIndex, visibleIds)` | 보이는 미완료 항목 사이에서 `targetIndex` 위치로 이동 |
| `dropIndex(orderIds, dragId, targetId, after)` | 드래그 앤 드롭의 최종 위치 계산 |
| `normalizeOrder(todos)` | `[미완료..., 완료(최근 완료 순)...]` 불변 조건 복구 |
| `rollover(todos, today)` | 이월 + 지난 완료 삭제 |
| `getProgress(todos)` | `{ total, done, percent, byCategory: { work, personal, study } }` |
| `filterTodos(todos, filter)` | 필터 적용 |
| `isValidTodo(item)` / `sanitizeTodos(list)` | 저장 데이터 항목 검증 / 잘못된 항목 제거 + 순서 복구 |
| `sanitizePrefs(prefs)` | 필터·마지막 카테고리 설정값 검증 |
| `toDateKey(date)` | `Date` → 로컬 `YYYY-MM-DD` |
| `formatDateLabel(date)` | `Date` → `2026년 10월 1일 (목)` |

- 변경할 것이 없으면(빈 입력, 없는 id, 이동 불가 등) **입력 배열을 그대로 반환**한다. 호출부는 `next === todos`로 변경 여부를 판단한다.

### 4.4 상태 흐름
```
사용자 입력 → ui.js 이벤트 핸들러 → app.js의 dispatch(action)
  → Todos.* 순수 함수로 새 상태 계산 → TodoStorage.save() → TodoUI.render(state)
```
- 렌더링은 상태 전체를 받아 목록을 다시 그린다 (하루 20개 규모라 충분히 빠름). 단, 편집 중인 항목과 포커스는 렌더 후 복원한다.
- 사용자 입력 텍스트는 `textContent`로만 넣는다 (`innerHTML` 금지 → XSS 방지).

- 최대 폭 640px, 가운데 정렬. 좁은 화면(< 480px)에서는 버튼을 축소.
- 다크 모드: `prefers-color-scheme`을 따른다. 별도 토글 없음.
- 색상은 CSS 변수로 정의 (라이트/다크 각각).

### 5.1 접근성
- 체크박스는 실제 `<input type="checkbox">`를 쓰고, 이름은 `aria-label`("보고서 초안 작성 완료")로 붙인다. 텍스트를 `<label>`로 감싸면 텍스트 더블클릭(편집 시작) 때 체크가 두 번 토글되므로 쓰지 않는다.
- 아이콘 버튼에는 `aria-label` (예: "보고서 초안 작성 삭제").
- 키보드만으로 모든 기능 사용 가능 (Tab 이동, Enter/Space 실행, Esc 편집 취소).
- 진행 바는 `role="progressbar"`와 `aria-valuenow/min/max`.
- 토스트는 `role="status"` (`aria-live="polite"`).

## 6. 오류 처리

| 상황 | 처리 |
|---|---|
| 저장 데이터 JSON 파싱 실패 / 구조 불일치 | 원본을 `todoapp.v1.backup`에 보관, 빈 목록으로 시작, 상단에 "저장된 데이터를 읽지 못해 새로 시작합니다" 1회 안내 |
| 개별 항목의 필수 값 누락·잘못된 카테고리 | 해당 항목만 버리고 나머지 유지 |
| 배열이 "미완료 → 완료" 순서를 어김 | 로드 시 상대 순서를 유지한 채 정렬해 복구 |
| `localStorage` 쓰기 실패 (용량 초과·시크릿 모드 등) | "저장하지 못했습니다. 새로고침하면 변경 사항이 사라질 수 있어요" 경고 배너. 앱은 메모리 상태로 계속 동작 |
| 다른 탭에서 데이터 변경 | `storage` 이벤트 수신 → 다시 로드 후 렌더 |

## 7. 테스트

### 7.1 자동 테스트 (`tests.html`)
- 외부 라이브러리 없이 간단한 `test(name, fn)` / `assertEqual(a, b)` 헬퍼를 직접 작성.
- 브라우저로 열면 통과/실패 목록과 합계를 표시.
- 대상:
  - `addTodo`: 위치(미완료 맨 아래), 공백 입력 거부, 200자 제한
  - `updateTodo`: 내용/카테고리 변경, 빈 text 무시
  - `removeTodo` / `restoreTodo`: 원래 위치 복원
  - `toggleTodo`: 완료 시 완료 목록 맨 위, 해제 시 미완료 맨 아래, `completedAt` 처리
  - `moveTodo` / `reorderTodo`: 경계(맨 위/맨 아래), 필터 적용 시 보이는 항목끼리 교환
  - `rollover`: 미완료 이월, 지난 완료 삭제, 오늘 항목 불변
  - `getProgress`: 0개, 일부 완료, 카테고리별 집계
  - `toDateKey`: 자정 직후·UTC 경계 (예: 로컬 00:30)
  - 저장 데이터 검증: 손상 JSON, 잘못된 항목 제거, 순서 불변 조건 복구

### 7.2 수동 점검 체크리스트
- [ ] `index.html` 더블클릭으로 실행됨 (서버 없이)
